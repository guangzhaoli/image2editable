# Affinity：原生可编辑论文图

适用于用户指定 Affinity、Affinity Designer 或已有 Affinity 工程。文档核对日期：2026-09-27。先识别实际应用版本，不把 Designer 2 的能力或文件格式直接套到新版统一应用。

## 确认版本和操作入口

1. 查看当前应用、文档标题和版本；有多个工程时，明确本次目标。先完成一个任务范围内、可见的小操作，确认实际控制路径。
2. **新版统一 Affinity：**官方于 2026-09-15 宣布应用内脚本、内置编辑器、Scripts Panel 和示例库，脚本可覆盖矢量、像素和布局。[官方发布说明](https://www.affinity.studio/blog/affinity-automation-scripting-claude)。先检查当前版本是否已有该入口，读取应用提供的示例/API 帮助，再编写该版本真正支持的代码。官方宣布有脚本能力不等于任意对象 DOM 已被本技能验证。
3. **已有可用连接器：**先发现真实工具及其 schema，再执行它支持的对象操作。官方同时介绍了可选 Claude AI Connector；这不证明当前 Codex 已有连接，也不构成安装、登录或改变账号的要求。
4. **Designer 2 或脚本入口不可用：**使用可用的原生界面自动化；必要时用简单 SVG/PDF 建立规则对象，再在应用中检查与保存。不要声称所有 Affinity 版本都没有脚本，也不要假设旧版本拥有新功能。
5. 使用 Computer Use 时，观察当前菜单和控件再操作；不要固化屏幕坐标。画布点击失败但 AX 菜单可用时，可以继续独立的保存/导出工作，同时明确未完成的直接编辑检查。不能用其他未经提供的 UI 控制技术绕过工具限制。

Affinity 脚本不是 Illustrator JSX。没有核实接口时，不编造 `app.activeDocument`、Illustrator DOM、通用 HTTP 服务或 Affinity Python SDK。

## 载入与建立对象

- 新图建立任务自己的文档；修改现有图时，沿用已有画板、分组和字体。大幅重建前另存副本，不覆盖用户的唯一版本。
- 有原论文 PDF 时先定位页面和图号。以可编辑内容打开/导入，再检查图层树；源 PDF 可能是矢量、位图或两者混合。若导入对话框提供文字编辑优先选项，按需求选择，并重新核对断行、字距、公式和字体替换。不要将“PDF 打开成功”等同于全部文本可编辑。
- 放置的 PDF/SVG 可能仍是单一嵌入或链接内容。查看是否能进入内部对象；不能时选择合适的打开/转换流程，或者重建必要标签和路径。不要为增加对象数量盲目拆散所有裁剪组。
- 框图使用原生矩形/圆角矩形、曲线、箭头、艺术字/框架文字及分组。Designer 2 官方列有箭头、节点编辑、分组/图层、嵌入与链接等能力；新版的具体入口以实际界面为准。[官方 Designer 2 功能](https://affinity.help/designer2/zh-Hans.lproj/pages/Introduction/keyFeatures.html)。
- 重复模块可复制后修改；用户只改一处时，检查关联符号、共享样式或全局颜色是否会改变其他对象。
- 精确布局优先用变换、对齐和分布控件。先核对单位与尺寸，再输入数字；不要将 SVG 像素、文档点和毫米混为一谈。
- 保留 live text；转换为曲线后虽然仍是矢量，但不能像原文字那样更换字体或编辑内容。公式需转曲时保留原始文本源并记录。[官方转换说明](https://affinity.help/designer2ipad/de.lproj/pages/ObjectControl/converttocurves.html)（该页为 iPad 文档，只引用转换含义，不照搬其菜单位置）。
- 显微图、照片、热图等保留科学图像本身，可编辑化其外围标签。检查链接资源，避免工程只在当前机器可见。

## SVG / PDF 导入抽查

截图复刻先按 [取色与原位描绘](reference-preparation.md) 准备底图、色板与区域素材，校准变换后在应用内锁定参考层。用原生形状/节点/文字在同一位置重建；新版本的 Image Trace 可用于局部不规则素材初稿，不替代文字与语义连接。

本机 3.3.0 的“矢量”菜单已观察到“图像描摹…”和“转换为曲线”。当未选中可用图像时命令会置灰；菜单存在不代表本轮已执行描摹或验证其质量。Designer 2 不沿用这一观察。

先验证代表性对象，再扩展整图：

| 对象 | 检查 |
| --- | --- |
| 普通文字和希腊字母 | 内容可进入编辑，字体正确，未变整块位图 |
| 上下标或公式 | 符号、基线、比例正确；转曲情况有记录 |
| 连线与箭头 | 起终点、方向、线宽和虚线节奏正确 |
| 分组模块 | 独立选取、移动/修改能力符合要求 |
| 栅格科学图像 | 像素内容、链接和标尺关系保持 |

更多交换规则见 [矢量交换](vector-interop.md)。一份看起来正确的导入预览不足以证明原生编辑能力。

## 保存、导出、重开

1. 使用实际应用的原生保存功能。Designer 2 的 `.afdesign` 与新版统一应用的原生格式分别处理；以当前“另存为”对话框提供的扩展名为准，不通过重命名伪造原生文件。
2. 记录目标画板、尺寸、颜色空间和需要保留的文字/路径。分别保存原生工程和用于论文排版的 PDF/SVG；投稿要求决定导出配置，不能把“PDF 用于打印”等预设当作通用合格标准。
3. 隐藏临摹参考层，检查最终导出区域。导出后解码检查裁切、透明度、公式、线条和字体；再用 `figure_compare.py` 与参考对照。
4. 重新打开原生文件，检查代表性文字、路径、组和资源。将“已保存”“已重开”“已直接编辑对象”和“已导出对照”分别记录。
5. 要求同时交付 `.ai` 时，需要在 Illustrator 实际打开、检查和保存；不要从 Affinity 写一个 `.ai` 文件名就宣称完成跨软件原生交付。

## 本技能创建时的实机证据

在 macOS Affinity **3.3.0 build 4850** 上，用明确标为合成示例的 SVG 完成了：打开 → 图层树中保留分组名称 → 原生另存为 **`.af`** → 导出 PDF → 关闭并重新打开 `.af`。导出的 PDF 有可提取文字，渲染预览已目视检查。

这是该版本、该测试图的基础流程证据，不能推广为任意 PDF/SVG 都无损导入。本次没有实际验证文字替换、路径节点编辑、Affinity 脚本 API 或 AI Connector；使用技能时仍需按任务完成相应检查。

旧版操作的查阅入口是 [Affinity Designer 2 官方帮助](https://affinity.help/designer2/English.lproj/index.html)。新版能力先查应用自带帮助与 [当前官方更新说明](https://www.affinity.studio/blog/affinity-automation-scripting-claude)，避免过时的“无脚本”结论。
