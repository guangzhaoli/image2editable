# 从论文或需求自主设计可编辑视觉

目标是让方法通过图形被理解，并把这份视觉设计保留为可修改的工程。内容证据决定科学含义，选定视觉目标决定构图与表达，统一 spec 驱动 SVG / 原生对象 PPTX。脚本执行和检查确定性约束，不替代论文阅读、审美判断或实际编辑验证。

## 1. 明确内容、用途与已有决定

沿用用户的受众、语言、软件、内容范围、已接受方向和已授权修订。记录最终物理尺寸与阅读场景：论文栏宽、整页图、投影或近距离 poster 需要不同密度。未给印刷规格时采用合理工作尺寸并说明，不假称符合某会议标准。已有认可的视觉目标继续有效，不因换轮次、换作者或进入重建阶段重复索要批准；局部修改也不重启全图设计。

并行制作时，各绘制者使用各自文件目录；共享桌面的应用操作集中交给一个执行者。子任务不要在文件渲染期间另行驱动正在使用的编辑器。无界面的文件转换与实际 GUI 操作分开记录，遵守当前环境的工具和权限约束。

实际阅读目标论文的方法、相关公式/算法、原图及 caption；poster 按内容范围补读实验与限制。为重要事实、输入输出、表示、训练/推理状态、控制/数据流建立稳定 ID 和来源定位。区分作者结果、作者解释、用户设想与本次设计选择。图文冲突或缺失数据留有记录，修正范围依据证据；不能用生成器补造数值、样例结果或连接。缺失内容只影响相关部分，其他工作继续。

## 2. 选择方法特定的视觉表达

先梳理关系，再按 [同类视觉参考检索](visual-reference-search.md) 使用网络搜索工具查找内容相近的成品：图片看相近题材与媒介的图片，poster 看实际同类海报，论文图看相关方法的架构图。实际查看原图/PDF，记录版本、图号、查询与取舍，并把学到的规律落实为具体布局决定。内容来源与风格来源分开。研发参考见 [调研与适配](design-research.md)，不能用通用制图论文或工具名称替代当前领域的实际图例。

把关键机制转成可见对象与操作，而非仅转成模块标题：例如用一致的样本与掩码表示分解，用有类型的 token/张量条带表示拼接，用代码、报告和工具对象表示产物流转，用物体姿态、坐标与轨迹表示空间变化。抽象算法可用准确的数学/结构几何，不必硬添照片。选择有解释价值的局部放大图；不是每个阶段都要相同大小或相同容器。

同一个实体或变量从样例图变成抽象表示、或跨视角/阶段出现时，要让读者看得出对应关系。点、方向、区域、token 类型等应在相关对象上有相符的锚点、颜色、标签或引线；把未定位的几何小图放在照片旁边，不能代替这种对应。时间变化则用必要的状态/姿态序列表示，并区分解释性示意与真实观测。

如果把卡片里的角色名称换掉，整幅图仍适用于任意方法，而本可直接展示的关键机制只剩说明文字，这份设计尚未解决任务。给每张卡片加图标不能修复这个问题。相同框适合确实等价的算子或重复单元，不按矩形数量判断好坏。颜色、线型、形状、符号应有可追踪的含义，必要时加简短图例。

## 3. 形成并审阅完整视觉目标

把检索得到的具体布局规律、重点区域和空间分配写入视觉稿提示词；参考只能改变表达方式，不能改变目标方法的事实。检查无功能的空白带、过大的标题/容器以及重复说明，将空间交给关键样例、机制或必要路线。保留分组和文字的安全间距，按内容组织紧凑版面，不用统一填充率代替审美判断。

多区域、含样例/插画或需要呈现内部机制的自主设计，**在原生重建前须有足够展开的全图视觉目标**。它可以是用户已选参考、生成的全图构图稿，或已成形的原生视觉草稿。应能实际看到区域比例、样例身份与视角、表示与变换、关键路线、文字层级和信息密度；只有标题框线或文字计划还不够。简单算子图、复刻、组件提取和已有工程局部修改不强制新增此步骤。

**丰富科研主图的默认分支是先生成整图视觉稿，再重建。** 用户没有提供已选定的完整视觉目标，且图中包含多区域、图像样例、空间/时序或内部机制时，使用可用的内置 ImageGen 展开全图设计。不能仅因为已取得论文素材或原生脚本能画框线，就跳过这一步。已接受的完整目标、简单数学/算子图、用户要求直接矢量绘制和已有工程局部修改沿用前述例外，不额外调用生图。

调用前按 [生成输入包](imagegen-input.md) 汇合前面的需求、内容关系与参考观察。沿用 `design-plan.json` 的事实/节点/关系 ID，选择与本图直接相关的内容；保留精确标签、数字、必要原文/图注和未确定项，不把整篇论文及全部搜索结果原样堆入提示词。可用且有帮助的原论文图、样例和视觉参考图作为真实图像输入，逐张标明 content / style / edit-target 的作用与借鉴范围；文字事实决定含义，风格参考只约束指定表达。参考缺失按明确的文字观察降级，不能把 URL 或路径文字称为已附图。

遵循 ImageGen 的当前工具/skill 约定，不另装模型或擅自改走外部 CLI。提示词写清区域比例、可见的数据/物体表示、样例身份、关键路线、色彩含义、字体和最终物理尺寸，并说明哪些样例只是解释。为投论文的主图预留合理版面，先约束可用宽高，不能无限拉高画布来使字号检查过关。保留完整提示词、有序附图及来源/哈希、实际调用参数与结果。组装检查只证明输入已准备，不能证明调用已发生或科学内容正确。工具不可用时才采用有实际图形与路线的本地视觉草稿作为降级分支，并记录原因、精细度限制和未验证的视觉质量；缺工具不增加审批关卡。

查看全图和关键局部，分别核对：科学关系是否正确；方法特定的表示是否真的可读；区域、图像和文字是否形成统一的视觉语言。对照输入包检查关键事实覆盖、指定参考的实际作用，以及是否混入风格参考的模块/结果。生成草案中的伪文字、错公式、错误端口、混乱训练状态和假样例均不能当作事实依据。先修正或明确标出待重建纠错，再进入原生构建。用户接受视觉方向不意味着接受其中的科学错误。

当不同布局确实影响理解时比较候选，记录选择理由；无需每次凑固定数量。选定后在计划里保留视觉目标路径/哈希、各区比例与锚点、样例/符号角色、字体层级及需要纠正的事实。后续重建的目标是保留这份选定表达，不在“变成可编辑”时重新设计成稀疏卡片。

## 4. 准备可用素材并安排出版尺度

科学图像优先来自用户文件或原始论文资源。PDF 有嵌入图像或矢量时，提取原始高分辨率对象，再按需要裁切；不要把页面缩略图或低分辨率截图放大充当清晰素材。核对页面/对象、裁剪范围、像素尺寸、最终放置尺寸与有效分辨率，保留哈希和来源。样本在多个区域重复出现时保持身份和对应关系。原资产中已烘焙的坐标/注释明确为栅格内容，不声称可单独编辑。

生成的解释性场景、纹理或图标独立存放，声明性质，不能替换真实观测或实验结果。连续场景可保留为一张素材，需要独立替换的主体分开准备。整页视觉目标只是构建参考；不能把它作为唯一交付图片。标题、方法标签、需修改的公式/数字与语义连线另外重建。

在布置细节前把字号换算到**最终物理宽度**：

`最终字号(pt) = spec 字号(px) / 画布宽(px) × 最终宽度(mm) / 25.4 × 72`

例如 180 mm 宽论文图可先以关键标签约 7 pt、次要注释约 6 pt 作为可配置设计下限，再依据投稿要求、字体和实际样张调整；它不是所有图的通用规范。1800 px 画布按此宽度输出时，7 pt 约需 24.7 px，6 pt 约需 21.2 px。角标、矩阵头和符号也要在真实尺寸下辨认。poster 则按实际观看距离设定层级，不能套用论文图下限。

密度过高时优先缩短标签、合并重复说明、把定义/共享条件/次要公式移到 caption 或补充图，为关键机制和证据图像留空间。不要靠自动缩字、过大的屏幕预览或低清小图来掩盖问题。需要的 caption 内容同步保存，避免移出图后丢失科学含义。

## 5. 将选定设计映射为原生对象

按区域把视觉目标映射到 spec 的形状、路径、live text、独立图像和有意义的分组，保留构图比例、样例规模/裁剪、表示层次、连线归属、符号和字重。重要连接按来源/目标/端口核对；跨区路线由上层统一安排。对事实错误做有依据的局部修正，并记录它为何偏离视觉目标。复用组件库可节省重复劳动，但不得把不同表示强制装入同一模块模板。

具体产物也需要保留差异：文献集合、带结构的研究计划、代码修改、结果图、逐步填充的稿件和批注，不应在重建中全部退化成同一个文档图标。缺少真实数据时，可用无数值的结构性示意表示产物类型，并在 caption 中说明其示意性质；不要虚构实验数值，也不要因此删掉本来有解释价值的视觉结构。把视觉目标中的关键表示列成简短清单，对照最后的成片逐项找到它们。

文字、规则几何和语义箭头优先原生重建；照片、渲染场景或复杂纹理按声明作为局部素材。后端覆盖不了某种外观时采用保留其表达作用的近似或明确例外，不默默删去样例、张量/状态结构、细节图和关键排版。当前字段读 [渲染约定](spec-renderer.md)，额外设计语义放计划侧车，不伪造 renderer 字段。

```sh
node scripts/render_figure.mjs figure-spec.json --check
node scripts/design_audit.mjs design-plan.json figure-spec.json --stage draft --out work/draft-audit.json
node scripts/check_route_labels.mjs figure-spec.json --out work/route-labels.json
node scripts/render_figure.mjs figure-spec.json --out work/render-01 --format both --runtime-modules /actual/node_modules
```

按用户目标选择格式，不无故增加交付。上述检查能发现契约、引用或端点对应问题，不能认证设计质量或引文正确性。

路线检查报告中的候选需结合实际像素逐项处理，`unknown` 留给视觉审查；退出码为 0 只表示报告成功生成。它不检查菱形内字形、所有独立路径或箭头头部，因此仍须按下文查看实际成片。

## 6. 看最终文件，修复后再看

审查实际准备交付的文件导出，而不是另一份中间图。对丰富设计同时比较选定视觉目标与当前工程：构图、图像、视觉编码和文字层级是否在重建中退化；有意修正应能由科学证据或用户意见解释。核对检索参考促成的具体改进是否落实，并在最终尺寸查看空隙的用途、区域比例和阅读节奏。新设计不以复制源论文几何或像素相似分数为目标。

分别记录以下结果：

- **科学含义：**关键节点、输入输出、训练/推理、分支/回路、状态与数值逐项回到来源；美化或精简后复查。
- **视觉表达：**读者能从图形指出机制、对象变化和关键路线，而不只读框内段落。检查全图层级及决定性的细节，不以图标数、形状数或无溢出代替判断。
- **最终尺寸可读性：**在声明宽度的 PDF/打印样张或明确尺寸的 proof 上检查小字、角标、箭头、矩阵和图像细节，再放大找技术缺陷。记录真实输出尺寸；大屏清晰不是纸面清晰的证据。
- **实际编辑：**在最终工程的临时副本上改有代表性的文字、移动或重着色一个机制组件，检查相关路径及未改区域，再保存、重开、导出。若声称目标软件内可编辑，证据必须来自该软件。ZIP/XML 盘点和文件工具重导入仅支持相应文件层面的结论。

丰富科研主图在有委派能力时，让**未参与绘制的读者**在交付前核对。先从实际尺寸的成片回答关键机制问题，再查看论文与视觉目标；分别检查科学含义、具体视觉表示、目标保留、两种实际交付格式和可编辑证据。不要把作者自评或检查通过的宣告作为审查依据。没有独立读者能力时明确这一限制，并分开做内容与视觉复查，不能称为独立审查。

根据这次独立审查的具体缺陷继续修复并复查受影响区域；读者发现错误不代表要从头再生成整图。保留对象 ID、依据、修改和新输出，优先处理科学错误，再处理阅读和构图；局部修复同时检查邻接关系。单纯“脚本通过”或对象更多不是进步。绑定实际检查的 spec 与输出哈希，修改后更新受影响的审查证据。

SVG 和 PPTX 都在交付范围时，分别查看二者实际渲染。特别检查 Unicode 小写下标、数学字母、上标和罕见符号；字体名称存在不等于包含这些字形。字形缺失时，用经过核实的字体，或把普通基线字母拆成小字号、明确偏移的 live-text 对象并分组；不要把某个渲染器的正常显示当成其他格式也通过的依据。既要能看见正确公式，也要能继续修改变量。

对每条有标签的分支、反馈和判断路线，实际沿箭头走一遍，并检查文字周围的空隙。让线绕开文字的完整字形区域；不要用“仍能猜出文字”作为线穿字的通过依据。判断菱形的文字应避开斜边，连接线不要从模块边界开始却没有可识别的业务源/目标。保留足够的路由沟槽；通过局部改线、缩短标签或增加适当间距修复，不用整幅缩字掩盖。独立审查指出关键缺陷后继续修复并重看，作者自检轮数不能充当交付终止条件。正式消融/重复实验的预算和原始失败记录则照预先约定保留。

应用或验证能力不可用时继续完成可用工程，明确尚未进行的检查；不能伪造原生通过、print-ready 或科学正确性。未解决的重要科学错误不得包装成已完成成品。工具/权限限制与可继续修复的设计问题分别说明，不由此新增无依据的审批流程。

## 7. 交付与重复性主张

交付目标工程、最终预览、可执行 spec 和必要 caption，简述设计保留、纠错、素材/公式编辑边界及未完成验证。阅读摘要标明独立身份。后续再生成前同步已接受的原生修改，或明确改由原生工程作为主文件，避免覆盖用户工作。

普通任务完成本次作品及相应检查即可，不强制三类案例各两次等试验。只有用户要求重复性评估，或准备声称流程稳定/改进有效时，才预先固定案例、输入、预算和独立运行条件，保留所有结果并作恰当比较；具体研究协议属于该研究任务。一次漂亮样例、若干脚本测试或重复使用同一作者上下文都不能建立稳定性主张。
