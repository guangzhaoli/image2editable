# SVG / PDF 中间文件与原生编辑

在大量规则框图、重复对象或图表中，矢量交换文件能减少重复操作。它是进入目标软件的一条路径，是否成功以该软件中的实际对象和导出结果为准。

## 优先保留已存在的内容

1. 用户给出的原生工程：延续原工程和图层。
2. 原论文矢量 PDF / SVG：尝试以可编辑内容打开目标页，检查文字、路径、裁剪组和嵌入图像。PDF 本身也可能只有整页位图。
3. 只有截图：重建图形/标签，保留真正需要的栅格区域。

“置入/Place”可能创建一个链接或嵌入对象；“打开/Open”通常会尝试转换文档。两者行为随格式/应用变化，检查图层树，而不是只看菜单是否成功。

## 生成可移植 SVG

- 显式 `width`、`height` 与一致的 `viewBox`，记录单位。使用简单的 `g`、`rect`、`path`、`circle`、`line`、`text` 和稳定 `id`；不要依赖 SVG 编辑器一定保留 `id` 为对象名。
- 尽量使用明示的 fill/stroke、线宽与坐标，减少 CSS 继承、滤镜、复杂遮罩和外部资源。导入不支持效果时，优先改写为可编辑路径，再选择局部栅格化并声明。
- 每个完整标签保持一个合理文字对象；复杂上/下标可用 `tspan`，但导入后检查基线和字距。不要为“看起来是矢量”将所有文字一开始就转曲。
- 箭头 marker 需要检查导入结果；若丢失，使用显式的线/曲线路径与三角箭头，并作为同一语义组。
- 嵌入必要的图片或交付相对路径资源；缺失链接不能靠当前机器缓存掩盖。
- 不用外部脚本或 `foreignObject` 承载论文图主体；普通 PDF/SVG 导入不能保证保留浏览器布局。

## 原生文件检查

导入一个代表性 panel 后，先核对：一处正文文字、一处上下标、一组箭头、一处虚线/透明/裁剪对象以及一张实际需要的栅格图。确认路线可行，再扩展整图。

对象数量不能单独证明可编辑性。拆成数千个字形路径的标签可以缩放，但未必适合改字；一个能双击进入的组与单张嵌入图片也不是同一能力。编辑性报告写明：

- live text / outlined text / raster text；
- native editable paths / groups / placed compound content；
- 必要的 raster scientific panels / 仅作参考的背景层。

保存时使用应用提供的原生保存功能；不手工伪造 `.ai`、`.afdesign` 或新版 Affinity 扩展名。原生文件、用于投稿的 PDF 和 PNG 预览各自验证。检查导出边界、字体、链接图像和透明效果。

## 尺寸和排版

先确定最终论文列宽或用户给定尺寸，再调字号和线宽。PDF 点为 1/72 英寸；SVG 用户单位不能不经核对就当毫米。不要为套用某一历史模板而强制单栏/双栏宽度。

检查单个 panel 的视觉重建后，再检查整图在实际尺寸中的文字可读性、panel 间距、标号位置和图例顺序。
