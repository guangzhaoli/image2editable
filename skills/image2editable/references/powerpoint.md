# PowerPoint：沿用 v2 的论文图复刻流程

目标为可继续编辑的 `.pptx`。继续提取 spec、色板与素材、参考图原位置入、重建对象、导出对照。v2.1 的程序化入口见 [统一 spec 渲染](spec-renderer.md)：同一份输入可生成原生文字、形状、自由路径和分组。精确路由采用固定路径，改 spec 后重算端点；它们不具备软件内拖动模块时自动重路由的能力。

## 选择真实执行路径

- 已打开 PowerPoint 或已有 PPTX 时，定位正确文件与幻灯片，沿用尺寸和已有内容。大幅重建前另存副本；局部修改只改目标对象。
- 当前有可用 PowerPoint 连接器时，按实际工具 schema 操作；否则使用可用界面工具或能生成原生对象的 PPTX 文件工具。不要假设 Windows COM、VBA、AppleScript、Office.js 或某个连接器在所有宿主可用。
- 在 Codex 的 Presentations 技能可用时，读取其中与本次文件操作相关的实现/验证说明，使用它提供的运行时和工具。论文原图决定比例、样式和对象；忠实复刻所需的原生形状、文字与箭头优先于普通演示文稿的风格建议。
- 没有 PowerPoint 时可先生成和检查 PPTX；标明尚未在 PowerPoint 中打开、编辑或原生导出。LibreOffice、Keynote、浏览器预览和文件工具渲染不能冒充 PowerPoint 实测。
- 旧 `.ppt` 需通过实际软件转换成 `.pptx` 再操作，不改后缀伪装格式。

## 画布和参考底图

1. 一张独立论文图默认用一页自定义比例的幻灯片，不自动加封面、标题装饰或改成 16:9；已有演示稿则保持其页尺寸，在既定区域内等比放置。
2. 记录参考像素坐标到幻灯片单位的同一映射。若参考宽为 `Wpx`、目标宽为 `Win`，则 `x_in = offset_x + x_px * Win / Wpx`，高与字体按同一比例处理。使用其他单位的库应先换算；不要混用 CSS px、pt、inch 和 EMU。
3. 置入原图，设置精确 X/Y/W/H，命名 `REFERENCE_DO_NOT_EXPORT`，放到底层。用画板边界和结构锚点校准，不通过肉眼拖拽估比例。
4. 用选择窗格管理对象顺序、名称、显隐和当前版本提供的锁定能力。支持锁定时锁住底图；不支持时保留参考工作副本，或将原图设置为工作幻灯片背景。
5. 背景图片与锁定图片仍可能被导出。最终文件/导出前隐藏或移除参考对象，背景参考则恢复正式背景；检查实际输出。不要把 Illustrator 的非打印模板层语义套到 PowerPoint。

Microsoft 的[选择窗格说明](https://support.microsoft.com/en-us/powerpoint/use-the-selection-pane-to-manage-objects-in-documents)描述了排序、显隐、分组与锁定；实际可用入口取决于平台/版本。使用[自定义幻灯片尺寸](https://support.microsoft.com/en-us/powerpoint/change-the-size-of-your-powerpoint-slides)时，留意尺寸改变对既有内容的缩放选项，不改变全局默认主题。

## 对象映射

| spec 内容 | PowerPoint 对象 | 检查 |
| --- | --- | --- |
| 标签、段落、上下标 | 原生文本框或形状内文字 | 字体真实样式、内边距、基线、行距、换行和溢出 |
| 框、圆、圆角模块 | 原生形状 | 尺寸、位置、圆角、填充和描边 |
| 简单语义连接 | 原生直线/肘形/曲线连接线，尽量连接对象端口 | 起终点、箭头所在端、移动模块后的路由 |
| 精确复杂线路由 | 原生自由曲线/形状路径，必要时独立箭头并分组 | 形状可编辑；若不能自动跟随模块，要明确说明 |
| 复杂图标 | 可编辑自由形状，或说明边界的局部 SVG/位图素材 | 不能将矢量图片宣称为独立模块/可编辑文字 |
| 显微图、样本、热图、照片 | 原素材图片 | 内容、比例、裁剪、标尺与资产来源 |
| 有真实数据的统计图 | 适用时用原生图表，或保留数据来源的矢量路径 | 刻度、单位、图例和数值；不编造数据 |

连接线的 `head`/`tail` 命名可能与库的方向约定有关；渲染后确认箭头真的指向目标，不凭参数名字判断。为了精确临摹手工固定的曲线路由，允许使用自由曲线，但要说明其与自动连接线的区别。

文字不要默认启用自动缩小来掩盖不匹配。按参考设定文字框内边距、段落间距和行距；先检查代表性标签的实际渲染。复杂公式优先保留可用的原生公式或文字；若用矢量公式图片，则交代不能直接改公式文本。

按语义命名和分组：`panel-a`、`encoder`、`labels`、`connections` 等。背景、文字和连接的前后顺序应服务于原图，避免把整页合并成一个难编辑的对象。

## SVG / PDF 的边界

插入 SVG 通常得到一个图形/图片对象。Office 的 SVG 编辑能力允许部分格式调整，某些版本提供 **Convert to Shape**；它不能保证恢复原来的文字对象、连接端口和语义分组。Mac/Windows 的可用能力需当场确认，不跨平台假定菜单一致。[Microsoft SVG 说明](https://support.microsoft.com/en-us/office/graphics-visuals/edit-svg-images-in-microsoft-365)。

因此，整图只有一个 SVG 图片对象的 PPTX 不满足“所有标签、模块、箭头可分别修改”。局部复杂图标允许保留 SVG，但主体应由原生对象重建。PDF 插入也不作为可编辑形状导入的保证。

## 文件检查与实际检查

运行 `scripts/pptx_inspect.py figure.pptx --out inspection.json` 可只读盘点：幻灯片尺寸、顺序、文字/字体、形状/自由路径、原生连接线、分组、图片与 SVG 图片、隐藏对象、参考标记，以及连接对象 ID。

脚本只读取 ZIP/XML，不修改文件、不访问外部链接、不调用 PowerPoint。它不测字宽、不渲染、不校验科学关系，也不能证明对象在实际应用里都可编辑；输出不是质量通过证书。

最终检查沿用 v2：

1. 对照 spec 检查文字、关系、单位、刻度和色板。
2. 保存 `.pptx`，重新打开；在选择窗格中定位代表性文字、模块和连接。修改副本中的一个标签，确认可以改文字；检查路径/形状节点以及连接端口行为，按任务需要取样。
3. 从 PowerPoint 导出预览或 PDF。若用 PDF 渲染成 PNG，读取实际页面尺寸并选择对应 DPI，使比较画布匹配；不盲目套用 Affinity 的 DPI。
4. 隐藏参考后使用原有 `figure_compare.py` 对照，修正受影响对象。不同渲染器的抗锯齿差异和真实布局错误分开判断。
5. 交付 PPTX、需要的 PDF/PNG、验证说明。明确哪些部分为原生文字/形状，哪些保留为图片，以及是否完成 PowerPoint 软件内验证。

## 工具示例（仅在相应运行时可用时）

Codex Presentations 当前 JavaScript API 使用 `Presentation.create({slideSize})`、`slide.shapes.add(...)`、`slide.shapes.connect(...)` 与 `PresentationFile.exportPptx(...)`。几何和数值字号采用 96 DPI 的 CSS px，明确的点字号使用对应 pt 字段；先读安装版本 API 文档。不要把这些单位套到采用英寸的其他库。

这只是生成 PowerPoint 原生对象的一种执行方式。软件分支不要求切换绘图策略，也不把普通介绍性幻灯片当作论文图复刻。
