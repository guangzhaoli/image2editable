# 可编辑科研图与视觉设计

把论文内容、创作需求或参考图转为用户指定软件中可以继续修改的视觉工程。完成标准分别检查**内容与科学含义、视觉表达、对象可编辑性**。复刻检查与原图匹配，自主设计检查是否有效传达指定内容；不把像素相似度当成新设计的目标。丰富主图在缺少已选全图视觉目标时，默认先用可用的内置生图工具展开构图，再按经核查的目标重建原生对象；不要把取得素材或会画矢量框线当作跳过视觉设计的理由。简单图、用户指定直接矢量绘制及局部修改按对应分支执行。

## 先选择工作模式

- **给定参考学习风格，优化已有图或生成新图：**读取 [参考风格适配与图文视觉 spec](references/reference-style.md)。实际查看参考，记录配色、字体气质、布局、图像媒介或光色中要采用的部分，并说明怎样适配本图。用图文混合 spec 保存原参考、局部样本、布局标注、色板与文字分析；通过现有生成输入包将选定图片和观察一起传入。已有可编辑工程优先改其对象，只有栅格目标时以真实 edit-target 编辑；内容、精确文字和指定保持项仍以本任务为准。
- **自主生成框架图、poster 或可编辑图文：**读取 [自主设计流程](references/autonomous-design.md)，按成品类型执行 [同类视觉参考检索](references/visual-reference-search.md)。调用 ImageGen 前按 [生成输入包](references/imagegen-input.md) 汇合需求、核对过的内容关系和实际查看的视觉参考；可用且相关的原图/参考图随提示词一起提供，逐张限定用途。对于多区域、含图像或需要表现内部机制的丰富设计，先完成并审阅全图视觉目标，再映射为可编辑对象；不能把源内容换成同款文字卡片和箭头就视为完成。没有目标论文的纯创作可从用户brief出发，不强造论文背景。
- **复刻已有图：**使用下文原位测量、取色、贴底、描绘和对照流程，默认不重新设计。
- **提取组件与样式：**读取 [组件库与配色清单](references/component-library.md)，保留来源和可编辑快照。
- **已有工程局部修改：**保留用户范围和已接受区域，优先改现有对象；无需重新做完整调研或生成全图。

自主模式的 `design-plan.json` 保存内容证据、关系、选定视觉目标及重建决策，`figure-spec.json` 是渲染器唯一的绘图参数输入。用 [设计审查约定](references/design-plan-contract.md) 检查对应关系；结构检查通过不等于视觉质量通过。用户已接受的方向和已授权修订在后续轮次继续有效，无需重新审批。修复生成草案中的事实错误，同时保留已选构图、样例组织和文字层级。

生成输入包是上述计划的选择与组装侧车，负责把已有分析实际交给 ImageGen；它不另建绘图坐标协议，也不取代科学依据。参考图缺失时保留具体文字观察并注明未附图；输入准备成功与实际工具调用分别记录。

需要图文记录时，使用 `visual-spec.html` 与对应的 `visual-spec.json`、本地参考素材和诊断板。页面里的图片是实际打包素材，生成调用使用选定原图或裁切，不把 HTML/链接当作附图。视觉 spec 记录学习与适配依据；最终坐标仍只放进 `figure-spec.json`。

截图复刻默认采用：**提取可追溯的 spec / 色板 / 素材 → 原图原位贴底并锁定 → 在同一坐标上描绘 → 隐藏参考后独立验收**。spec 与原图共同驱动绘图，不让下一阶段只凭文字描述重新猜测位置。已有原生图的局部修改不需要重新准备整套底图。

各模式共用 spec 与渲染入口，不在两个后端分别维护坐标。已在原生应用手工修改的工程先保留副本；生成器不会自动读回这些改动。

## 选择执行路线

- 先沿用用户指定的软件、现有工程和修改范围。在 Affinity、Illustrator、PowerPoint 中选择本次目标；只有明确要求跨软件交付才做多份。
- 软件未指定时，根据当前打开的工程和已安装软件选择并说明。多个目标均可用且交付选择会影响后续编辑时，询问偏好；期间可以分析参考图。
- 使用当前真实可用的连接器、脚本接口或 Computer Use。先确认应用版本和一个小操作可用，不猜测 API、菜单坐标或导出参数。
- **Affinity：**读取 [Affinity 工作流](references/affinity.md)。新版 Affinity 与 Designer 2 的自动化能力和文件格式分别判断。
- **Illustrator：**读取 [Illustrator 工作流](references/illustrator.md)。按当前环境选择原生连接、JSX 或界面；诊断脚本只做对象盘点。
- **PowerPoint / PPTX：**读取 [PowerPoint 工作流](references/powerpoint.md)。沿用 v2 的 spec、取色、素材与贴底策略，将对象映射为原生文本框、形状、连接线、自由曲线和分组；交付 `.pptx`。程序化重建读取 [统一 spec 渲染](references/spec-renderer.md)，使用 PPTX 后端。先保留参考图的画布比例，不自动改成演示文稿模板。
- Affinity/Illustrator 批量建立规则几何时，若原生脚本入口不可用，可用 SVG/PDF 中间文件导入；先读 [矢量交换与可编辑性](references/vector-interop.md)。导入后在目标应用内检查、修复和保存。PowerPoint 中整图 SVG 默认仍是图片对象，不能据此声称文字和模块可独立编辑。
- 应用不可用时，继续制作可用文件并标明未完成的原生检查。PowerPoint 可先通过支持原生对象的文件工具生成 PPTX；Affinity/Illustrator 可交付中间矢量文件。不要改扩展名伪造原生格式。

## 复刻：从参考到可编辑工程

### 1. 锁定参考与任务

记录参考路径或来源、PDF 页码（从 1 开始）、图号、目标 panel、裁剪范围、输出软件和尺寸。引用线上论文时实际读取对应页；缩略图仅用于定位。

优先检查用户已提供的矢量 PDF/SVG/原生源文件，能保留的文字和路径直接复用。只有截图时，测量布局并重建。参考本身模糊、被裁切或文字无法辨认时，将未知项写明，不自动补成研究事实。

默认为忠实复刻。用户要求重设计、替换模块、翻译或改配色时，保留其授权范围并记录变化，不把临摹扩大为重新设计。

阅读 [科学内容与复刻验收](references/fidelity-and-science.md)。统计图若缺原始数据，区分已有矢量曲线复用、标注为近似的读图数字化、以及需要真实数据的重绘。

### 2. 建立简洁的图形规范

截图复刻或复杂图使用 [spec 约定](references/spec-contract.md)，保存可直接定位对象的 `figure-spec.json`；可附简短 `figure-spec.md` 说明。简单局部修改只需记录受影响对象。规范包含：

- 坐标系：参考宽高、原点、裁剪位置、缩放/平移映射及关键锚点；明确最终物理尺寸（有要求时）。
- 文本清单：原文、位置/基线、数学符号、上/下标、字号、目标应用实际字体/字重和对齐；保留未知或替代项。
- 对象清单：稳定 ID、类型、bbox/中心点、控制点或线路由、前后层级；箭头绑定源/目标对象及端口。
- 样式：每种颜色的用途、HEX/RGB、色彩空间、取样框与统计方法；线宽、虚线、圆角及估计依据。
- 素材清单：文件、哈希、来源页/裁剪框、透明度状态、原位坐标，以及“保留栅格 / 复用矢量 / 仅作描摹参考”的用途。
- 数据与语义：单位、坐标刻度、线性/对数轴、图例映射、关键数值、数据来源。

先确定结构关系与布局锚点，再修字体和装饰。多 panel 图先统一尺寸、边距、标号和图例；已有论文格式要求优先于默认审美。未测得值标为估计，不把图中测量的 RGB 当成原作者矢量文件的真实填色。

### 3. 提取证据与准备原位底图

读取 [取色、素材与原位描绘](references/reference-preparation.md)。优先复用原始矢量和嵌入素材；只有栅格图时，在未调暗、未叠图的原文件上取样。平色区域避开文字、描边和抗锯齿边缘；记录采样框、众数/中位数及像素分布，必要时换多个区域复核。

可用 `scripts/prepare_reference.py` 从明确指定的色样框和素材框生成 `palette.json`、`assets.json`、可视色板、取样位置图、`reference-measurements.json` 和 `trace-board.svg`。它不自动识别整图结构，不自动去背，也不把准备板算作复刻成品。测量记录允许未定项；将它补全、迁移为 [可执行 spec](references/spec-renderer.md) 后才能渲染，不把准备记录直接冒充完整 spec。

在目标应用中置入原参考，以图板边界和锚点校准位置/比例；锁定 `REFERENCE_DO_NOT_EXPORT` 图层，在其上创建重建层。透明度可调低帮助描绘，但颜色从未调暗的原文件或已验证色板获取。SVG 不提供通用的锁层保证，导入后必须在应用中确认锁定。

PowerPoint 用选择窗格管理并命名参考图片与重建对象。若当前版本支持锁定则锁定；否则使用参考工作副本或固定的幻灯片背景，按 [PowerPoint 分支](references/powerpoint.md) 在最终导出前移除参考。锁定、隐藏与不参与导出分别检查。

### 4. 依 spec 与底图描绘

使用可辨认的图层/组，如 `panel-a`、`modules`、`connections`、`labels`、`plots`、`images`。按实际复杂度组织，不机械增加空层。

程序化重建先读 [统一 spec 渲染](references/spec-renderer.md)，运行 `render_figure.mjs --check`，再按目标选 SVG 或 PPTX 后端。它只消费 spec 与通过哈希检查的本地素材，不再分析原图或自行布图；原图仍用于测量和叠合验收。覆盖不了的原生对象能力明确标为不支持，扩展已定义字段和后端或保留可追溯的手工对象，不退化为整图图片。简单已有工程的局部手改可以直接操作应用，不为它强制重建全图。

- 对照底图，按 spec 的几何值建立矩形、圆角框、椭圆和钢笔/节点路径；用数字变换与对齐工具固定坐标，再检查叠合，不仅凭鼠标拖到“差不多”。箭头保持正确的起终点与前后层级；需要路径和箭头头部分开时将其分组。
- 自动描摹按区域使用：原生 Image Trace 可为不规则图标/轮廓建立初稿；规则框和文字优先用原生对象。整图自动描摹得到的字形路径、填充轮廓和碎片不等于可编辑标签或语义连线。检查后按需要重建。
- PowerPoint 按当前能力使用原生形状、文本框、连接线及自由曲线；不假设它有 Affinity/Illustrator 的 Image Trace。SVG 转换为形状仅在实际支持时使用，转换后的字形轮廓不当作可编辑文字。
- 保留用户拥有的显微图、照片、渲染图和热图等必要栅格素材；不要为“全矢量”重画科学图像中的观测内容。
- 文字尽量保持 live text；先在目标应用验证一组代表性文字的实际字体/字重、基线与宽度，再批量铺开。缺字体时说明替代和重排影响，不能仅依赖 SVG 的字体列表/weight 属性。公式若只能保留为路径，明确这是矢量可缩放但不能直接改公式文本。
- 每完成一个区域，交替显隐底图检查边缘双影与锚点；半透明/描边视图用于定位偏差，正式颜色检查恢复正常合成。最终导出隐藏参考和辅助线图层，并检查候选成片没有依赖整图截图冒充重建。
- 延续已有工程时保留用户改动和已接受区域。先另存副本再运行可能覆盖内容的重建脚本；不改变全局首选项、安装扩展或升级应用来完成普通绘图。

原生编辑器是最终交付环境。脚本执行成功、文件存在、应用能打开、对象可编辑是不同证据。

### 5. 导出、对照、修复

从目标应用导出当前图板/画板的预览；不要拿中间 SVG 的浏览器截图证明原生渲染结果。使用相同画板边界和已知尺寸对照，必要时显式统一渲染分辨率并记录。

用 [对比工具](references/comparison-tool.md) 的 `scripts/figure_compare.py` 生成并排图、叠加图、差异图和数值报告。尺寸不同默认报错；任何裁剪、缩放必须显式指定。比较指标只说明像素差异，不能证明科学正确或对象可编辑。

按影响修复：内容/连接错误 → panel 和整体比例 → 文字、图例、坐标轴 → 线宽、颜色和微小间距。检查实际投稿尺寸下的可读性，也放大检查上下标、箭头和裁切。对用户只要求换色或改字的任务，重点验证受影响对象及相邻布局，并快速对照整张画板，确认指定区域之外没有变化；尤其检查共享样式、全局色板或关联符号是否影响其他对象。

当下一轮修正仍能减少已知关键差异时继续；达到用户接受的相似度、或差异受缺失字体/数据/工具限制时，交代剩余差异。不要设置通用的“SSIM 超过某值即可通过”。

### 6. 验证交付

按任务检查以下独立证据：

1. **语义：**标签、符号、箭头、分支、单位、刻度和图例与参考/用户要求一致；近似数据已声明。
2. **视觉：**目标应用导出的预览经过对照；剩余差异有具体位置和原因。
3. **编辑：**代表性的文字、路径/模块和分组能在应用中单独选中编辑；原生文件保存后可以重新打开。检查缺失字体、链接和导出中的裁切。

通常交付：原生文件（PowerPoint 为 `.pptx`）、论文排版所需的 PDF/SVG（按用户或刊物要求及软件能力）、PNG 预览，以及一段简洁验证说明。复杂或高保真任务保留 `figure-spec.md`、对照图和 `verification.md`；不强制给用户堆积工作文件。

说明原生工程保存/重开状态、文本是否可编辑、路径化公式和保留的栅格区域、字体替代、数据近似及尚未验证的部分。链接准确输出文件；任何未完成的原生验证都直接标明。
